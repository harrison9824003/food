# 簡訊驗證碼

對應里程碑 6 第一段。訂位流程見 [booking.md](booking.md)。

## 為什麼需要

之前用「訂位代號＋手機號碼」查詢與取消。但手機號碼不是祕密（訂位單、客服、朋友都知道），
代號只有 8 碼，所以那只是「知道兩個字串」而不是「證明這支手機是你的」。
現在改成**收簡訊驗證碼**：通過之後換到一張短效憑證，之後訂位、查詢、取消、付款都靠這張憑證證明持有手機。

## 流程

```
輸入手機 → POST /api/phone/send-code        → 寄 6 位數驗證碼（走 Queue）
輸入驗證碼 → POST /api/phone/verify          → 回憑證 token（15 分鐘）
之後的請求帶標頭 X-Phone-Token: <token>
   ├─ POST /api/reservations          建立訂位（憑證的手機必須就是填寫的手機，否則 403 PHONE_MISMATCH）
   ├─ GET  /api/my/reservations       這支手機的所有訂位（不必記得代號）
   └─ POST /api/reservations/lookup | cancel | pay    手機號碼完全由憑證決定，請求內容裡的不採信
```

沒帶憑證或憑證無效／過期 → `401 PHONE_NOT_VERIFIED`。查詢、取消、付款用別支手機的憑證 → `404`（和「代號不存在」一樣，不洩漏代號是否存在）。

## 安全設計

| 項目 | 做法 |
|---|---|
| 驗證碼強度 | 6 位數，`random_int`（CSPRNG） |
| 儲存 | **只存雜湊**，不存明碼。用 HMAC-SHA256（應用程式金鑰）而不是 bcrypt：6 位數只有一百萬種可能，bcrypt 擋不住離線暴力破解，真正的防線是「5 次作廢」；HMAC 讓資料庫外洩時沒有金鑰就無法反推 |
| 比對 | `hash_equals` 固定時間比較 |
| 有效期 | 5 分鐘；同一時間只有最新寄出的那一組有效，舊的立即作廢 |
| 錯誤次數 | 5 次作廢，之後連正確的碼也不能用，必須重新取得。計數在「鎖住該列的交易」內完成，同時送出多個猜測也不會超過上限 |
| 一次性 | 驗證成功後該組驗證碼立即作廢，不能換第二張憑證 |
| 重送冷卻 | 60 秒。用 `Cache::add`（Redis `SET NX`，原子）：同一手機同時送兩個請求，只有一個搶得到鎖；若改成「先查上次寄送時間再寫入」，兩個請求都會看到冷卻已過而各寄一則 |
| 限流 | 同一**手機**每小時 5 則、同一 **IP** 每小時 20 則，任一超過就擋。只限 IP：攻擊者換 IP 就能灌爆同一支手機；只限手機：攻擊者可以對大量不同號碼狂發、刷爆簡訊費。驗證端點另限 IP 每 10 分鐘 30 次 |
| 不洩漏資訊 | 寄送的回應不論這支手機有沒有訂位都一樣；「沒要過驗證碼」「過期」「打錯」回完全相同的訊息 |
| 憑證 | `Crypt`（AES-256-GCM，含驗證標籤）加密，內容只有手機號碼與到期時間，**無法偽造或竄改**，也不洩漏號碼（有測試），不需要資料表 |
| 憑證有效期 | 15 分鐘 |
| 正式環境 | **一律嚴格**：即使 `SMS_REQUIRE_VERIFICATION=false` 也要驗證（有測試）。這個開關只讓本機與既有測試可以略過簡訊 |

## 發送

- 走 Queue（`SendSmsJob`）：廠商的延遲或故障不會拖慢或卡住顧客的請求。
- **失敗以指數退避重試**：第一次加三次重試，間隔 30 秒、2 分鐘、10 分鐘，用盡後記錄 `sms gave up` 並放棄；顧客可以在冷卻過後自己重寄。
- `ShouldBeEncrypted`：job 內容（含驗證碼）在 Redis 裡是加密的，不是明文。
- job 帶著觸發它的 `request_id`，worker 的日誌可以和顧客那次操作串起來。

### 驅動（`SmsDriver` 介面）

| 驅動 | 說明 |
|---|---|
| `mock`（預設） | 不發簡訊，內容寫進 `mock_sms_messages`。**正式環境誤設成 mock 會直接拒絕**（否則顧客永遠收不到驗證碼卻看不出錯誤） |
| `every8d` | 互動資通 Every8d HTTP API |

> ⚠️ **Every8d 驅動沒有對真實服務驗證過**：我沒有 Every8d 帳號。請求格式依官方文件實作，
> 測試以 `Http::fake()` 驗證「送出的請求長什麼樣」與「對各種回應（`-` 開頭的錯誤碼、未發送、HTTP 錯誤、逾時、沒設帳號）的處理」，
> 沒有實際發出過簡訊。要用的話請先用你的帳號小量實測。

### 本機開發：看不到真的簡訊怎麼辦

`.env` 設 `SMS_MOCK_INBOX=true` 後，前台的驗證面板會多一個「開發用：模擬簡訊收件匣」按鈕（前端另需 `VITE_SMS_INBOX=true`，docker-compose 已設定），
點一下就看得到驗證碼簡訊內容。`GET /api/dev/sms?phone=` 只在非正式環境且明確開啟時可用，否則 404（有測試）。

## 日誌

獨立的 `sms` channel（`storage/logs/sms-YYYY-MM-DD.log`，保留 30 天）：要求驗證碼、驗證成功、錯誤次數用盡、發送成功／失敗／放棄。
**手機號碼只記末三碼（`*******456`），絕不記驗證碼**（有測試逐行檢查）。

```bash
docker compose exec php-fpm sh -c "tail -n 50 storage/logs/sms-*.log"
```

## 前台

- **聯絡資料**步驟：手機號碼旁的驗證面板，通過前「下一步」不能按；改了號碼就不再算已驗證、要重新驗證。
- **我的訂位**：輸入手機 → 驗證 → 列出這支手機的所有訂位，每筆可取消、可付款；可以「換一支手機」。
- 憑證存在 `sessionStorage`（關掉分頁就沒了）；伺服器回 `PHONE_NOT_VERIFIED` 時前端自動清掉並回到驗證。
- 停在確認頁超過 15 分鐘導致憑證過期：送出時會被導回聯絡資料重新驗證，其他資料都還在。

## 設定

| 環境變數 | 預設 | 說明 |
|---|---|---|
| `SMS_DRIVER` | `mock` | `mock` 或 `every8d` |
| `SMS_REQUIRE_VERIFICATION` | `true` | 是否必須先驗證手機（正式環境無視，一律必須） |
| `SMS_MOCK_INBOX` | `false` | 開發用收件匣 |
| `SMS_SEND_PER_PHONE_PER_HOUR` / `SMS_SEND_PER_IP_PER_HOUR` | `5` / `20` | 寄送限流 |
| `EVERY8D_UID` / `EVERY8D_PWD` / `EVERY8D_URL` | — | Every8d 帳號 |

驗證碼長度、有效期、錯誤上限、冷卻、憑證有效期、重試間隔在 `config/sms.php`。

## 測試

```bash
docker compose exec php-fpm php artisan test --filter=Sms
```

`phpunit.xml` 預設用**寬鬆模式**（直接採用請求裡的手機號碼），讓既有的訂位與付款測試不必處理簡訊；
`Sms/StrictModeTest` 與 `Sms/PhoneVerificationTest` 自己打開嚴格模式，涵蓋憑證、跨手機隔離、限流、冷卻、過期、次數上限等。
